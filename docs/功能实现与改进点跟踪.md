## 0. 一句话现状

平台的**主链路（上传 → 准备 → 标注 → 封板 → 训练 → 守门员 → 发布）已经可用**，PostgreSQL 影子库经本轮收口 + 回填后与 JSON 真值一致。当前风险集中在**工程完整性**（关键文件未入 git、CI 失效）和**边界防护**（解压、鉴权），而不是功能缺失。

### 2.2 部署固定顺序

```
1. 改代码 → 重建镜像（/app/backend/src 不在 volume 挂载列表，scp 进容器无效）
2. docker compose up -d
3. python backend/scripts/migrate_to_pg.py --prune-only     # 清游离，不重灌
4. python backend/scripts/backfill_has_label.py             # 第二步必跑，见 2.3
```

### 2.3 最容易踩的坑：`has_label` 会被冲成 NULL

`has_label` 是**运行时从每图标注 JSON 现算的派生字段**（`bool(ann.get("boxes"))`），task.json 的 items 里**只有 `annotated`**。因此：

- 对已存在任务调 `shadow.replace_task_items(task.json["items"])` → PG 已回填的 `has_label` 全部变 NULL；
- `migrate_to_pg.py` **全量重灌 tasks** 同样会冲掉 → 重灌后必须补跑 `backfill_has_label.py`；
- 收口层规则：`sync_task(id, with_items=True)` **只允许在 create_task 时用**。

## 3. 当前阶段禁止实现的复杂功能（黑名单）

判断标准：**需要重写渲染层 / 引入新框架 / 大范围重构**的，一律不做。平台后面要被拆解融入他人平台，投入产出比极低。

| 编号 | 禁止项 | 为什么禁 | 替代做法 |
|---|---|---|---|
| 🚫 X-01 | **拆分巨型 Vue 文件**（DatasetAnnotate 198 KB / Train 101 KB / Models 92 KB / ModelDetail 67 KB / DatasetUpload 60 KB） | 无组件库、无 composables 复用层，拆分等于重写整个前端；标注页的画布交互与快捷键耦合在单文件里，回归成本极高 | 只在**新增页面**时按组件化写；老页面保持现状 |
| 🚫 X-02 | 前端引入 UI 组件库（Element Plus / Naive UI 等） | 会牵动全部 6 个页面的样式与交互 | 继续用现有手写样式 + `GlobalDialog` |
| 🚫 X-03 | 自建标注画布的多图层 / 掩码编辑器 | ultralytics 分割训练只需 polygon 轮廓，已够用 | 保持 `boxes` + `polygon` 两形态 |
| 🚫 X-04 | 多用户 / 权限体系 / 登录 | **待拍板**：平台将嵌入他人平台，鉴权应由宿主承担。当前无鉴权 + CORS `*` 见 `S-03` | 若确定独立部署再议；嵌入场景由宿主网关收口 |
| 🚫 X-05 | 把 JSON 真值源迁走、Postgres 转为主存储 | 现有全部服务按文件读写实现，迁移是重写级工程；影子库定位就是"可重建索引" | 保持"JSON 唯一真值 + PG 影子" |
| 🚫 X-06 | 用 ORM 关系/外键重构 `db/models.py` 8 张表 | 现在靠 `meta_store` 手写列白名单，重构会破坏 `migrate_to_pg` 与 `shadow` 的路径口径一致性 | 加列走 `engine.py` 自动补列机制 |
| 🚫 X-07 | 训练页 WebSocket 双向控制 / 实时超参热调 | SSE 单向日志已满足，双向控制要改 ultralytics 子进程协议 | 保持 SSE + 轮询兜底 |
| 🚫 X-08 | 推理服务（在线预测 API） | `API_DOCUMENTATION.md` 有该章节但**无对应路由**（`D-04`），属历史遗留；嵌入场景由宿主平台提供推理 | 文档标注"未实现"，不补代码 |

> 反面清单之外的事——**加防护、补收口、修文档、入 git**——都是当前阶段鼓励做的，因为它们不需要新框架。
