## 1. 系统拓扑

### 1.1 进程与请求链路

```
浏览器
  │
  ├─ 开发模式（本地）
  │   Vite dev server :3000
  │     ├── /            → Vue SPA（frontend/src）
  │     ├── /dev-api/*   → 反向代理剥前缀 → http://localhost:8000/*
  │     └── /static/*    → 反向代理（不剥前缀）→ http://localhost:8000/static/*
  │
  └─ 生产模式（单容器）
      Nginx :80（docker/nginx.conf）
        ├── /              → 静态 SPA（try_files → index.html）
        ├── /prod-api/*    → rewrite 剥前缀 → 127.0.0.1:8000/*
        ├── /static/*      → 127.0.0.1:8000/static/*
        └── client_max_body_size 20480m（20GB 上传上限）
              │
              └─ uvicorn :8000  src.main:app（单进程）
                    ├─ JSON 文件（backend/data/**）＝唯一真值源
                    └─ PostgreSQL 影子库（可重建的查询库）
```

### 1.2 后端启动时挂载的后台循环

`lifespan` 在启动时创建 4 个 asyncio 任务（[main.py](file:///c:/Users/41653/Desktop/yolo-main/yolo-main/backend/src/main.py#L13-L45)），关闭时全部 cancel：

| 任务 | 来源 | 职责 | 相关配置 |
|---|---|---|---|
| PG 影子库初始化（⚠ 内联 await，非 asyncio 任务） | `engine.init_db()` + `meta_store.seed_status_mapping()` | 幂等建表、状态映射种子；**PG 连不上只 warning，不阻断启动** | `PG_ENABLED` |
| 模型队列轮询 | `ModelQueueService.poll_loop()` | 定时把入队图片打包成标注任务 | `MODEL_QUEUE_POLL_SECONDS=300`、`MODEL_QUEUE_MIN_IMAGES=20` |
| 桶灌轮询 | `DatasetService.bucket_poll_loop()` | A 包标注完成自动灌接收桶、满额自动封板 | `BUCKET_POLL_SECONDS=60`、`SEAL_MIN_IMAGES` |
| 封板时间窗轮询 | `DatasetService.seal_poll_loop()` | 超期未封板的数据集自动兜底封板 | `SEAL_MAX_DAYS=7`、`SEAL_POLL_SECONDS=3600` |
| GPU 熔断监控 | `train_routes.train_service.gpu_watch_loop()` | 训练途中 GPU 利用率持续过低自动停训 | `GPU_ABNORMAL_UTIL_PCT=10`、`GPU_ABNORMAL_SECONDS=300` |

> ⚠ 这些循环**没有任何管理页面**。它们的开关只在 `backend/.env` / `settings.py` 里。排障时若发现"数据自己动了"，先查这里。

## 2. 功能模块总览

平台由 6 个功能模块构成，模块与页面的对应关系：

| 模块 | 职责 | 主要页面 | 后端路由前缀 | 核心服务 |
|---|---|---|---|---|
| M1 算法库/模型仓库 | 模型（=算法库根）的创建、归属、标签字典、版本、合并、发布 | Dashboard、Models、ModelDetail | `/models` | `model_service` |
| M2 数据集管理 | 上传、prepare、挂载模型、校验、封板、归档、桶灌、导出、删除 | DatasetUpload、ModelDetail(数据集 Tab) | `/datasets` | `dataset_service` |
| M3 标注 | 任务创建、逐图标注、AI 预标注、批量预标注、审核、导入导出 | DatasetAnnotate | `/annotations`、`/sam` | `annotation_service`、`sam_service` |
| M4 训练 | 作业创建、排队并发、GPU 选择、日志流、中断恢复、图表 | Train | `/train`、`/logs` | `train_service`、`device_manager`、`log_service` |
| M5 守门员与发布 | 训练产出的自动评估、退化拦截、强制覆盖、冷却期发布 | Models、ModelDetail(版本 Tab) | `/models` | `gatekeeper`、`model_service` |
| M6 样本池 | 困难样本库（按模型）、空白负样本库（全局），供混训抽样 | DatasetUpload(查看弹窗) | `/sample-pool` | `sample_pool_service` |

模块间依赖方向（单向，无环）：

```
M1 算法库 ←── M2 数据集（挂载归属）
M2 数据集 ──→ M3 标注（prepare 后建任务）
M3 标注 ──→ M2 数据集（导出标注回写、封板）
M2 数据集 ──→ M4 训练（封板产物作为训练输入）
M6 样本池 ──→ M4 训练（按比例混入训练集）
M4 训练 ──→ M5 守门员 ──→ M1 算法库（新版本入库/生产切换）
M1 算法库 ──→ M3 标注（标签字典是标注类别的唯一权威来源）
```

### 3.1 Dashboard.vue — 模型仓库首页

- **路由**：`/`，`name: Dashboard`，文件 27 KB

- **核心元素**

- **交互逻辑**
  - 点卡片 → `router.push('/models/{model_id}')`（[L347-L349](file:///c:/Users/41653/Desktop/yolo-main/yolo-main/frontend/src/pages/Dashboard.vue#L347-L349)）

### 3.2 DatasetUpload.vue — 数据集页

- **路由**：`/datasets`，`name: DatasetUpload`，60 KB
- **页面用途**：数据集全生命周期的操作台——上传、准备、挂载、审核、封板、导出、删除。
- **核心元素**
  - **上传卡片**：接受 `zip / tar / tar.gz / tgz`；归属方式二选一（选已有算法库 or 填 `model_code` 动态建库）；上传成功后自动触发 prepare

  - **数据集列表**：文件名 / 大小 / 阶段 / 训练状态 / 封板时间 / 图片数（待封板显示 `n/门槛`）/ 标签数 / 类别 / 自动任务 ID / 描述 / 标签

- **挂载时调用**：先 `POST /datasets/advance-buckets`（幂等触发灌桶），再 `GET /datasets`；查看弹窗按需 `GET /datasets/{id}`、`GET /datasets/{id}/tree`
- **行操作与接口映射**

| 操作 | 接口 | 说明 |
|---|---|---|
| 去标注 | 无接口，纯跳转 | `window.location.href = '/annotate?dataset_id=' + id`（[L560-L562](file:///c:/Users/41653/Desktop/yolo-main/yolo-main/frontend/src/pages/DatasetUpload.vue#L560-L562)） |
| 封板 | `POST /datasets/{id}/seal` | 传 `force` + `split_ratio`；数量不足需二次确认 |
| 审核通过 | `POST /datasets/{id}/approve` | 人工复核标记 |
| 撤回灌桶 | `POST /datasets/{id}/unpour` | 从接收桶退回 |
| 校验 | `POST /datasets/{id}/validate` | 重跑标注格式校验 |
| 编辑 | `PUT /datasets/{id}` | 仅 `description` / `tags` |

| 加入困难样本库 | `POST /sample-pool/hard` | 按模型 1:1 |

### 3.4 Train.vue — 训练页

- **路由**：`/train`，`name: Train`，101 KB
- **页面用途**：训练作业创建 + 队列监控 + 实时日志 + 产物浏览 + 中断恢复。
- **核心元素**
  - 数据集选择：主数据集 + **多数据集聚合**（统一类别空间）+ `aggregate_incomplete` 雪球自动带同业务未完成数据集
  - 优化目标：选择业务方向；启用预训练权重（yolov5/8/9/10/11 × 尺寸，或自定义 `.pt`）；指定业务模型做 base 微调；跨代迁移训练
  - 资源：GPU 节点选择（`GET /train/gpus`）
  - 超参：L2 智能推荐（`GET /train/suggest`）+ 高级参数（`lr0` / `optimizer` / `weight_decay` / `patience`）
  - 增强混训：`hard_sample_ratio`（默认 0.1）、`background_sample_ratio`（默认 0.05）、`recall_enabled`
  - 作业列表：状态、进度、日志面板、目录树（FolderTree）、停止/恢复/删除/重新训练
  - 失败提示：前端按日志规则给 9 类建议（显存不足、字体重载、权重损坏等），**每任务只提示一次**（`localStorage['yolo_train_failed_alerted']`，[L1800-L1812](file:///c:/Users/41653/Desktop/yolo-main/yolo-main/frontend/src/pages/Train.vue#L1800-L1812)）
- **接口映射**：`POST /train/jobs`、`GET /train/jobs`、`GET /train/jobs/{id}`、`GET /train/jobs/{id}/tree`、`POST /train/jobs/{id}/stop`、`POST /train/jobs/{id}/resume`、`DELETE /train/jobs/{id}`、`POST /train/prepare-weights`、`GET /train/business`
- **日志**：`subscribeLogsSSE`（SSE 主路）+ `pollLogsTail`（断线轮询兜底）+ `getLogLines`（末 N 行），状态进 Pinia `useLogStore`（[store/logs.ts](file:///c:/Users/41653/Desktop/yolo-main/yolo-main/frontend/src/store/logs.ts)）

## 4. 页面跳转与数据传递

### 4.1 跳转关系全图

```
                     ┌─────────────── 顶部导航（router-link，无参数）───────────────┐
                     │   /          /datasets      /annotate      /train     /models │
                     └──────────────────────────────────────────────────────────────┘

Dashboard (/)
  ├─ 点算法库卡片 ──────────────→ /models/{model_id}          参数：path params
  ├─ 新建库成功 ────────────────→ /models/{model_id}          参数：接口返回的 model_id
  └─ 空态「去模型管理」────────→ /models                        无参数

DatasetUpload (/datasets)
  └─ 行「去标注」──────────────→ /annotate?dataset_id={id}    参数：query
                                 ⚠ 用 window.location.href，整页刷新（非 SPA 路由）

DatasetAnnotate (/annotate)
  └─ 无出站跳转（跨页靠 localStorage 恢复现场）

Train (/train)
  ├─ 入站：?dataset_ids=、?library_root_id=
  ├─ 失败提示确认后 ───────────→ router.push({name:'Train'})   自我刷新
  └─ 作业行「查看模型」────────→ /models/{model_id}            参数：query-free path

Models (/models)
  └─ 无 router.push（详情动作全部为页内弹窗/抽屉）

ModelDetail (/models/:modelId)
  ├─ 「← 返回仓库」────────────→ /                              无参数
  ├─ 数据集行主按钮（动态）────→ /annotate?dataset_id={id} 或 /train?dataset_ids={id}
  ├─ 「查看详情」──────────────→ /datasets?focus={dataset_id}   ⚠ 目标页未消费该参数
  └─ 版本区「查看」────────────→ /train                          无参数
```

### 4.2 四种数据传递方式及其适用场景

| 方式 | 载体 / 键 | 写入方 | 读取方 | 语义 |
|---|---|---|---|---|
| **path params** | `/models/:modelId` | Dashboard、Train | ModelDetail L545 | 实体主键，进入详情页 |
| **query** | `dataset_id` | DatasetUpload L561、ModelDetail L690 | DatasetAnnotate L3390 | 「直达并复用该数据集的标注任务」，优先级高于本地恢复 |
| **query** | `dataset_ids` | ModelDetail L692 | Train L1844 | 预选训练数据集集合 |
| **query** | `library_root_id` | ModelDetail 发起训练 | Train L1841 | 预选产出归属算法库 |
| **query** | `focus` | ModelDetail L185 | **无人读取** | 设计意图：数据集页定位到该行（未实现） |
| **localStorage** | `annotate_task_resume` | DatasetAnnotate L1479 | 同页 L1505 | 标注断点续标（当前任务 + 当前图片 + 未保存草稿） |

### 4.3 后端跨模块的数据传递（真值层面）

## 5. 业务流程实现路径

### 5.1 主流程 A：上传 → 准备 → 标注 → 封板

```
① 用户进 /datasets，选压缩包 + 归属（选库 or 填 code）
   POST /datasets/upload
     → dataset_service.upload_dataset L328
       · 生成 dataset_id = ds_{YYYYMMDD_HHMMSS}
       · 原始包落 data/uploads/{dataset_id}{suffix}（保留，可重复 prepare）
       · 写 meta.json：status=uploaded, stage=collecting, model_id, library_root_id
       · shadow.sync_dataset(id)
       · 若填 code 且未命中 → 自动 create_empty_model 建空白库

② 自动/手动 prepare（幂等、可重试）
   POST /datasets/{id}/prepare  {split_ratio, classes}
     → 解压（_extract_zip L119 / _extract_tar L181，含 Windows 长路径与路径遍历防护）
     → 重组 v1/{images,labels}
     → 识别类别（txt / data.yaml / classes.txt）
     → 自动匹配并绑定模型
     → 标注格式校验
     → 生成 preview 缩略图
     → 若 labels_dict 仍为空 → init_labels_from_classes()（幂等，人工维护过的不覆盖）
        └ 紧接着 shadow.sync_model(model_id)（字典是 models.labels 的来源）
     → 图片数 ≥ AUTO_TASK_MIN_IMAGES(20) → 自动创建标注任务
     → 失败则 _rollback_model_binding_on_prepare_failure L374 解除挂载

③ 入队（绑定模型时）
   全部图片入 data/queues/{model_id}/queue.json 的 pending
   触发打包：达 MODEL_QUEUE_MIN_IMAGES(20) 立即 / 每 MODEL_QUEUE_POLL_SECONDS(300s) 定时
   打包 = 按 (dataset_id, version) 分组 → 取模型标签字典类别 → 创建或复用标注任务 → 清 pending → 写 history

④ 标注
   /datasets 行「去标注」→ /annotate?dataset_id=xxx
   GET /annotations/tasks/by-dataset/{id}（复用）或 POST /annotations/tasks（新建）
   GET /annotations/tasks/{tid}/items（列表，has_label 从每图 JSON 现算）
   画布标注 → POST /annotations/tasks/{tid}/items/{image_id}
     → 写 data/datasets/{ds}/annotations/{image_id}.json（strip_ann_bbox 只存点不存冗余矩形）
     → meta_store.update_task_item_has_label（影子库逐行回填）
   AI 辅助：POST /sam/auto-label | interactive-label | point-label | batch/start
   清理：clear-ai / clear-all / clean-overlaps；外部导入 import-yolo

⑤ 封板（两条路）
   手动：/datasets 或 /models/{id} 点「封板」→ POST /datasets/{id}/seal {force, split_ratio}
     三条件：status=prepared 且未归档；数量 ≥ SEAL_MIN_IMAGES（不足需 force）；标注/校验通过
     产出：images/{train,val,test} + labels/{...} + data.yaml（names 取标签字典英文码，无 v1 层级）
     seed=42 确定性划分；数据集转只读
   自动（桶灌）：POST /datasets/advance-buckets（前端进页先调）+ 后台 BUCKET_POLL_SECONDS 轮询
     A 包标注完成（JSON 标注数 ≥ 包图片总数）→ 按上传时间 FIFO 灌入模型接收桶
     累计满门槛 → 截 1500 个封成 ds_auto_{ts}，display_name = {code}_v{N}，剩余滚下一桶
   兜底：SEAL_MAX_DAYS(7) 超期未封板 → seal_poll_loop 自动 force 封板
```

### 5.2 主流程 B：算法库 → 数据集挂载 → AI 预标注

```
① /models 或 / → LibraryCreateModal → POST /models/libraries 或 POST /models
     → model_service.create_empty_model：写 model.json（empty=true, library_root_id, classes）
       + labels_dict.json（空字典）→ shadow.sync_model(id)
② 挂载数据集：
     路径 1：/datasets 上传时直接归属
     路径 2：ModelDetail 分区 C「挂载未归属数据集」→ GET /datasets/{id}/bind-check 探测类别序号错位
             → PUT /datasets/{id}/model {model_id, force}
③ 标签字典治理（预标注提示词的唯一来源）：
     PUT /models/{id}/labels（在用类别禁删、禁重排 index）
     POST /models/{id}/labels/suggest → Qwen-VL 从图片识别候选 → POST .../adopt 采纳
     POST /models/{id}/labels/sync-annotations（把字典变更刷进已存标注，带 backup_id 可 rollback）
④ AI 预标注：GET /sam/available → POST /sam/auto-label
     引擎链：YOLO-World / GroundingDINO / Qwen-VL（可多引擎 detectors 并行）
     去重：IoU≥0.5 与已有框合并；空白时三级重试（降阈 → 换引擎 → Qwen VLM）
     可选二次审核：qwen_enabled 时对结果调 qwen_audit_detections
     配置：GET/POST /sam/config（data/sam_config.json），服务器用 OLLAMA_QWEN_MODEL / endpoint 环境变量覆盖
```

### 5.3 主流程 C：训练 → 守门员 → 发布

```
① 入口：ModelDetail「用这些数据集去训练」→ /train?dataset_ids=…&library_root_id=…
② 参数装配：GET /train/gpus、GET /train/suggest（L2 智能推荐）、GET /train/business
   权重：POST /train/prepare-weights（本地未缓存的 .pt 从国内镜像下载到 models/custom）
③ 创建：POST /train/jobs
   → train_service.create_job L1062：写 data/jobs/{job_id}/job.json
     （dataset_id / dataset_ids / datasets[] / base_model / 超参 / hard_sample_ratio / background_sample_ratio）
   → 并发受 MAX_CONCURRENT_TRAIN_JOBS(3) 限制，超出排队
   → spawn 子进程 src/yolo/train_script.py
④ 观测：GET /train/jobs（列表，读侧 shadow.refresh_datasets 按 mtime 自愈）
        GET /train/jobs/{id}、GET /train/jobs/{id}/tree
        日志：GET /logs/stream（SSE）→ 断线 GET /logs/tail?offset= → GET /logs/lines?n=
⑤ ⚠ 跨进程写：train_script.py 在子进程内直接改 data/datasets/{id}/meta.json
   （stage / training_status / trained_at / last_trained_round）
   → 主进程写侧钩不到 → 读侧用 mtime 水位自愈（shadow._WATERMARK）
⑥ 产出：best.pt → models/registry/{new_model_id}/weights/best.pt + model.json
   （business / status / version / lineage / gatekeeper 报告）
⑦ 守门员 gatekeeper.py：
   评估失败（新模型 or 旧基准）→ rejected
   首版（同业务无生产模型）→ 直接晋升 v1.0
   非首版：new mAP50-95 必须严格 > 旧值（+1e-6）
   防偏科：逐类 AP 相对跌幅 > 5% → 退化判定；旧有新无 = -100% 严重退化
   通过 → promoted（status=production_ready），数据集 last_trained_round +1
⑧ 发布：POST /models/publish/pending 列出待确认 → 冷却期 PUBLISH_CONFIRM_COOLDOWN_HOURS(24h)
   → POST /models/publish/{id} 确认发布（旧同业务生产模型标 superseded）
   人工兜底：POST /models/{id}/override 强制设生产（记录原因）
   升级预标注：POST /models/{id}/promote-to-detector（同验证集对比 mAP 与速度，只写 sam_config.json）
⑨ 中断恢复：POST /train/jobs/{id}/resume（优先 last.pt → best.pt → base/original）
   后端重启后按 pid 用 psutil 接管孤儿训练进程
```
